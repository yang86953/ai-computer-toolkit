# computer-control-toolkit 接口参考

当任务采用该工具包时，项目通常位于 `~/data/code/computer-control-toolkit`，二进制与 Cargo 包名为 `ai-computer-toolkit`。实际路径、能力与调用约束从当前项目和安装版本读取。其他桌面或浏览器任务可直接选择宿主提供的适合工具，不必先构建此项目。

本项目控制目标为第三方前台软件，支持 Linux/Wayland 与 Windows 两条桌面路线，不提供后台隔离。UIX 平台层作为外部版本化依赖使用，包内不包含 UIX 源码或特定客户端扩展；UIX 自身应用的 AI 接口与验证归 UIX 项目。

## 首选直接工具

先看当前宿主实际工具列表：有 `computer_connect`、`computer_observe`、`computer_interact`、`computer_keys` 等就直接调用，按 `连接 → 截图确认目标 → 键鼠小步骤 → 核验返回图 → 断开` 操作。这些工具管理常驻连接、nonce 和临时图像，不要求任务开始时读源码、枚举全部能力或写调用包装脚本。

用户要求鼠标、快捷键操作或测试电脑控制时，直接操作目标界面，不以 Blender Python、控制台代码等应用脚本替代。若任务只要产物而未限定方式，再按实际能力选择应用协议。

没有直接工具时，先核实 MCP 接入是否缺失：本项目 MCP 入口就是 `ai-computer-toolkit` 二进制本身（**无参数启动即标准 MCP stdio 服务**），不依赖 Python 或额外适配层；它与 UIX 框架的后台 Agent MCP 不是一回事。接入、参数与失败边界见 [MCP 直接操作](references/mcp-control.md)。未加载时说明当前缺口，不称工具完全不可用，也不自动安装、重启宿主；在既有授权内可用下述 CLI 路线。

## CLI 发现与操作

需要定位目标、选路或排障时，用 `build-info`、`help`、`capabilities` 了解当前实现。`discover`、`sessions`、`inspect` 返回目标与快照，注意 `complete`、`truncated` 和 `warnings`；部分 provider 的空结果不证明所有应用都不存在。

使用实际返回且仍有效的 `sessionId`、`snapshotId`、`elementId`。需要目标能力判断时使用 `assess app --capability <能力及版本> --target sessionId=<目标>`。嵌套输入可用 `--input <file|->`，字段以实际 schema 为准。

优先选择适合当前动作的语义接口、应用协议或图像定位；视觉输入核对截图坐标、客户区与缩放。`candidate`、fixture 或 Portal 就绪并不保证目标可控。`--confirm` 和 `--allow-foreground` 表达已有授权，不创造授权。

在关键状态变化后观察动作结果；动作被接受与实际完成可能不同，按契约查询异步终态或读回所需结果。桌面输入前确认目标窗口、焦点和输入法；快捷键命中某次窗口不证明下一次仍有焦点。中文输入法可能改变 ASCII 合成输入。焦点变化或出现意外文字时先停止输入并重新观察，不连续补发。

## 按场景选择观察方式

动作通道与观察通道分别选择，以当前目标实际支持的接口、任务所需证据和延迟为准，不统一改成截图或帧流。

| 场景 | 优先方式 | 验证重点 |
| --- | --- | --- |
| 可读取控件、文档或业务状态 | 应用协议、DOM、无障碍树等语义接口；有事件通知则订阅 | 读回预期值或异步终态，不以请求已发送代替完成 |
| 静态界面、低频点击、偶尔查看结果 | 按需截图，确定的小批次操作后观察 | 核对目标、焦点与结果；不常驻高频采集 |
| 无语义完成信号的加载、弹窗、状态提示 | 支持时等待目标区域变化，再核验预期内容 | 变化只是触发核验的信号；画面稳定也不等于完成 |
| 拖拽、滚动、画布操作等连续视觉交互 | 支持时使用帧更新与局部变化反馈，分段控制 | 反馈延迟、目标是否移动、坐标是否仍有效；及时停止偏离操作 |
| 焦点切换、布局或缩放变化、意外弹窗、局部结果无法解释 | 重新观察足够上下文，必要时完整窗口或全屏 | 重建目标与坐标对应关系，不沿用过期局部定位 |

先确认安装版本提供相应能力；没有帧订阅或区域等待接口时，用有截止时间、按任务延迟需求设置间隔的按需观察降级，不虚构接口，也不自动重发写操作。只有全帧 `pixelDigest` 时，只能判断对应捕获图像是否不同，不能定位变化区域或证明业务完成。

帧流在本地过滤噪声、合并更新并保留最新画面，仅将关键帧或有上下文的区域交给模型，不逐帧推理。连续视觉反馈的预算、坐标失效和降级细节见 [连续执行与性能](references/continuous-execution.md)。

## 连续执行

复用仍有效的目标与连接，按确定的小成果顺序执行，逐请求检查终态。新界面、焦点变化、弹窗或结果不明时重新观察；截图按所需细节选分辨率，不固定每步全量发现或截图。

用户插话改变目标、取消、权限撤销或结果未知时，停止后续写请求并核实已发生效果，不盲目重放。按实际协议释放客户端资源，不终止他人的任务。

使用 MCP 时优先复用其已管理会话，不另起第二个 broker。手动维护 Portal 常驻会话、需要扩展批次/帧流或做延迟专项调优时读 [连续执行与性能](references/continuous-execution.md)，包含 nonce 取消、请求配额、收尾顺序与测量口径。

## 恢复与排障

- `STALE_SESSION`：重新发现并核对原目标，避免向过期对象重发。
- `OUTCOME_UNKNOWN`、部分执行或 `automaticRetryProhibited=true`：先核实已发生的效果，再处理未完成部分。
- `FOREGROUND_CONSENT_REQUIRED` 或权限拒绝：核对已有授权与实际缺口，遵循工具与宿主的权限流程。

先区分参数、过期目标、环境、应用故障与工具包缺陷。需要且已获准修改工具包时，读取其 `AGENTS.md`、相关 `contracts/` 和实现，以实际失败请求复现、修复并通过公开入口验证，然后继续原操作。单纯使用工具包不自动扩展为开发任务。

构建开发入口可使用现有锁文件执行 `cargo build --locked --bin ai-computer-toolkit`，并从 `target/debug/ai-computer-toolkit` 核对版本。报告时区分开发产物验证与已安装入口的实际结果。
