# 连续执行与性能

适用于 Portal 常驻会话、批次输入或工具包专项调优；简单语义操作无需加载全部优化细节。以当前安装版本契约为准。

## 会话与批次

- 已确认目标后复用仍有效的会话/连接；不要每次动作重新全量发现、读取整树或启动宿主。代际变化时才重新发现并核对原目标，不能按同名应用自动改绑。
- 第三方应用若有当前已核实的语义动作或状态等待接口，优先复用并验证所需终态，减少模型往返和固定 sleep；不能用 UIX 同名接口推断第三方支持，也不能把全部入队或发送成功当作已处理。
- Portal 桌面路线优先 `session-host desktop --socket` + `session-call desktop --input <file|->`，完整响应到达即返回，避免用终端轮询的固定等待。用 `exec_command` 托管长期宿主时设置 `tty:true`，或由已有持久进程运行时持有；读唯一 ready 后绑定 epoch，不自行重启并重放输入。
- 对目标/焦点已核实、步骤确定的操作，按有意义的小成果组织原 `steps` 批次，逐请求检查终态后连续执行，不必每个按键都回到模型。批次遵守实际 schema 的数量/期限；阶段末统一观察，新界面、焦点切换、弹窗或结果不明时提前观察。没有标准全局焦点保护时，不把批次说成自动防误输入。
- 当前 `interact` 的实测约束：`steps` 内所有 `wait` 的毫秒之和必须**严格小于**本次请求的 `timeoutMs`（MCP 默认 3000ms），单步 `wait` 上限 1000ms；按键、文本、点击与移动都不计入这条预算。`steps` 上限当前为 648（MCP schema 直接引用 broker 的同一个常量，不再各写一个数字）；单批另有展开工作单元上限（点击 3／移动 1／每键 2／每字符 4，合计 16384），文本密集批次先撞这条。把已确定的步骤合成一次调用、把 `wait` 压到 60–150ms，比逐步往返快一个量级；超限是整批拒收（不部分执行），修正参数即可用原帧重发。键盘与快捷键只送达持有焦点的窗口，批量发键前先确认焦点在目标窗口。
- MCP 路线要跨越多批时用 `computer_run`，不要自己串多次 `interact`：它在服务端循环「补帧 → 送一批 → 读回新帧」，一次调用最多 64 批 × 648 步，每批仍绑定当时最新帧。每批独立 `timeoutMs`（≤30000ms，也是该批 wait 合计的唯一上界），`totalTimeoutMs` 默认 45s、上限 600s，并受 MCP 客户端工具超时限制；`captureEveryBatches`/`maxFrames` 控制回读帧数。内部补帧沿用调用方 `maxDimension`，观察与运行用同一个值。run 期间其他调用 BUSY；出错默认停止，预检拒绝可跳过，「输入可能已送出」必停且不重放。
- 坐标步与其它步同一套预算，没有单独天花板：一次请求内绝对指针共用一个 emulation 会话，批末统一收尾，写缓冲的 `EAGAIN` 背压在请求 deadline 内重试而不是当断连。实测单请求连续 648 次绝对指针一次通过（64ms），649 步被预检拒绝且不投递、不伤会话。此前「坐标批 ≤64 步」的拆批经验已作废。
- 截图按需：可先用 `capture-frame` 的显式 `maxDimension` 预览（如 1280），小字或定位细节不足再取原图。预览坐标不是桌面输入坐标；不能拿缩小图摘要证明源画面不变。不得为提速省略结果核验或改动权限。
- 连续执行不等于无限会话或禁止取消。跟踪请求预算，在自然阶段边界收尾；普通 broker 账本为 1024 条，新版满载后另留独立取消/关闭/查询/退出配额，只用于收尾而非继续普通动作。逐个 `close` → 核对空 `sessions` → `shutdown`；具体配额从当前版本契约读取，旧安装版不假定已修复。
- 用户插话、目标变化、取消、权限撤销或结果未知时停止后续写请求。需要取消在途 Portal 输入时，另发绑定原 nonce 的 `input-cancel`；先核实已经发生的效果，不盲目重做整个批次。

## 变化驱动观察与降级

以下是选择与实现要求，不代表当前工具包已经提供帧订阅、区域等待或自动切换接口；以实际能力及 schema 为准。

- 为一次等待确定目标范围、预期结果、截止时间和观察预算。区域变化触发核验，静默或超时触发重新观察与诊断；不能把“若干毫秒不变”设为通用成功条件。有语义终态时优先用它结束等待，视觉信号辅助定位和解释。
- 只在连续交互或低延迟等待阶段开启持续观察，阶段结束释放订阅；复用已有授权会话，不为提速另建绕过权限的捕获链路。取消后停止后续输入，按协议终止观察并核实在途效果。
- 本地合并相邻更新、限制分析频率；光标闪烁、动画、视频等非目标噪声按任务过滤，目标区域内的提示不能一概忽略。短暂提示可使用有界关键帧缓冲保留；过载时限制队列，不让模型追逐过时画面，也不承诺不会漏帧。
- 区域坐标绑定对应的帧、目标及缩放关系；布局、窗口位置、分辨率或目标变化后重新定位。点击前若发现目标区域变化，重新核对目标，不直接使用旧坐标；检查仍不能消除检查与输入之间的竞态。
- 区域裁剪用于减少后续分析，但需保留理解状态所需的窗口标题、邻近标签等上下文。全帧摘要相同只描述当前捕获表示，缩小图摘要不能证明源画面不变；摘要不同也不能给出变化位置。
- 增量流若依赖基准帧，丢帧、序号不连续或尺寸变化时重新获取完整基准；无法确认最新画面时停止依赖旧坐标的输入。接口不支持或观察失败时，降级为有界单帧观察，必要时回到语义查询；不重放结果未知的动作。
- 区分原生增量捕获与“全屏采集后差分”：后者可能减少传输和模型分析量，但未必减少采集、拷贝与差分成本。按场景测量端到端完成时间、误判/漏检、CPU/带宽和模型调用量，不能只用帧率证明更快或更省。

工具包专项开发或调优时，参考智协项目文档中的 `docs/docs/Linux桌面快速调用.md` 与 broker 契约。测量分别记录传输、应用处理/呈现、观察与模型/工具往返的 p50/p95 和失败数；微基准提速不能证明整项操作已达到人工速度。
